Module session_queue 

Source
Expand description

Per-key actor queue for serializing concurrent access.

Each key (session id or slot id) gets at most one concurrent turn. Additional requests queue up (bounded by max_queue_depth) and proceed in FIFO order. This prevents SQLite history corruption from overlapping writes and ensures consistent session state transitions.

Two type aliases are exported over the same implementation:

  • SessionActorQueue — legacy /ws/chat path, keyed on session_id.
  • SlotActorQueue — dashboard path, keyed on slot_id (M1+).

The name slots on the internal HashMap predates the dashboard “slot” concept and refers to serialization slots in the queue.
